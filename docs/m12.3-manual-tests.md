# Manual Test Guide — M12.3

History panel + per-slot diff summaries. The user can open a side
drawer that lists every confirmed Phase-2 change in reverse-
chronological order, and each entry expands to show 1-2 sentence
diff summaries per affected slot.

Run on branch `M12.3-history-panel-and-diff-summaries`.

## What changed

### Diff summaries (server)
- `ChangeLogEntry.diffSummaries: { slotId, slotLabel, summary, ts }[]`
  is populated post-hoc as each slot regenerates during the iteration.
- New `summarize.diff_summary` prompt: takes `<slot_label>`, `<before>`,
  `<after>` and returns 1-2 sentences in plain past tense ("Added X",
  "Renamed Y to Z"). Uses `role: "fast"`.
- New `fireDiffSummary(...)` helper in `src/lib/operations/diff-summary.ts`:
  runs the LLM call on a `setImmediate` continuation, never blocks the
  caller, soft-fails on any error.
- New `IStorage.appendDiffSummary(sessionId, summary)` writes the result
  onto the most-recent ChangeLogEntry. If a summary for the same slotId
  already exists, the new one overwrites it (last regen wins).
- Wired into:
  - `workflow-stage.ts`, `screen-stage.ts`, `wireframe-stage.ts` — fire
    after each `setSlot` for the step's produced slot.
  - `phase2-cascade.ts` `runWireframeDataImpact` — fires for both
    `wireframeData` and `wireframeFiles` after the in-place patch.
  - `phase2-cascade.ts` `runWireframeHtmlImpact` single-item path —
    fires for `wireframeFiles` after the targeted regen.

### History panel (client)
- New `HistoryPanel` component: side drawer with reverse-chronological
  list of `ChangeLogEntry` rows. Each row expands to show per-slot
  `DiffSummary` rows ("Workflow Map: Added Save Draft workflow…").
- Toggle button in `DocumentPanel` header ("History").
- Rolling `changeLogSummary` is rendered above the entries when present
  ("Earlier changes (summarized)").
- The panel re-fetches `/api/sessions/[id]` on open and on Refresh
  click. Diffs generated by fire-and-forget calls won't appear in the
  initial fetch right after a cascade — click Refresh in a moment.

## What stays unchanged

- ChangeLog appends, sliding-window summarization, restore semantics,
  pipelineVersion bumps — all M12.1.5 / M12.2 behavior is unchanged.
- Initial generation does not produce diff summaries (no changeLog
  entry to attach to → fireDiffSummary silently no-ops).

## Verification (no LLM calls)

```bash
npm run typecheck       # clean
npm run test:pipeline   # 30/30 pass
npm run build           # production build succeeds
```

## Test 1 — Open History panel

1. Any session. Click "History" in the document header.
2. Expect: side drawer slides in. If the session has no changeLog
   entries yet, panel says "No confirmed changes yet."
3. Click "✕" or the dim backdrop → panel closes.

## Test 2 — Confirm a cascade, then open History

1. New session → walk to a Phase 2 review.
2. Send a change request → preview banner → Confirm.
3. After the cascade settles, click History. Expect:
   - One entry visible. Title = the change summary
     ("Added an X workflow"). Subtitle = timestamp + first impact step
     + "summaries pending" (if diff hasn't returned yet).
4. Wait ~5 seconds. Click Refresh.
5. Expect: subtitle says "1 slot${n} changed" (or whatever count). Click
   the entry to expand. The diff summary row(s) appear, e.g. "Workflow
   Map: Added an Archive task workflow that moves a task to an archived
   state instead of deleting."

## Test 3 — Multi-slot iteration ends with multi-slot diff

1. Lock a session (walk through to complete).
2. Send a workflow-rewind change (e.g. "Add a sharing workflow") at
   complete. Confirm. Walk through approves to relock.
3. Open History → entry for this iteration. Expand.
4. Expect: multiple `DiffSummary` rows — one for Workflow Map, one for
   Screen Inventory, one for Sample Data, one for Wireframe (depending
   on which slots actually changed). Each with a 1-2 sentence summary.
5. Confirm the version chip in the document header bumped to v2.

## Test 4 — Drift FLAG / Cancelled previews leave no entry

1. Send a change that drift-FLAGs (e.g. third-party sync against a
   contract that excludes it). Drift banner appears, no preview banner.
2. Open History → no new entry.
3. Send a COMPATIBLE change → preview → Cancel.
4. Open History → no new entry.

## Test 5 — Rolling summary appears past 110 entries

(Only practical with a temporarily-lowered threshold in
`src/lib/context/window.ts`.)

1. Lower `COMPRESS_THRESHOLD` to 12 and `VERBATIM_KEEP` to 10. Restart.
2. Trigger 11+ confirmed cascades.
3. The 12th will compress: oldest 2 fold into `changeLogSummary`.
4. Open History. The "Earlier changes (summarized)" section appears
   above the verbatim entries with a rolling summary blurb. The
   verbatim entries below are the most recent ten.

## Test 6 — Restore preserves the changeLog and its diffs

1. Build up some changeLog entries with diffs.
2. Roll back to Phase 1 → Done with unchanged contract → restore.
3. Open History. Expect: every entry + its diffSummaries are present
   (the suspended snapshot saved them and restorePhase2 brought them
   back).

## Known limitations

- Diff summary generation is fire-and-forget. If the server is killed
  mid-generation (dev hot reload, container shutdown), the entry's
  diffs may stay empty. They never auto-regenerate in this build —
  trigger another cascade or accept the missing diff.
- The fanout per-screen workflow_detail substep doesn't get its own
  diff summary (we only diff the step's produced slot, not its
  intermediates). Acceptable — the step-level diff covers the change.
- The HistoryPanel doesn't subscribe to live updates via SSE. The
  Refresh button is the manual sync. Could be improved later with a
  push channel.
